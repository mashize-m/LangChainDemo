# Agent 全流程实战总结

## 一、 课程核心模块分类与重点提炼

你的课程设计循序渐进地展示了 Agent 的四大核心能力：**工具调用（Tools）、自主执行（Agent Loop）、记忆（Memory）、人类干预（HITL）**。

### 1. 自定义工具与手动执行原理 (Lesson 01)

- **核心内容**：`@tool` 装饰器定义工具，手动接管大模型的调用请求。
- **逻辑流程**：用户提问 -> LLM 返回带有 `tool_calls` 的 `AIMessage` -> 本地解析 `tool_calls` -> 执行函数 -> 构造 `ToolMessage` 回传给 LLM -> LLM 生成最终回答。
- **重点/坑点**：
  - **Docstring 即 Prompt**：函数的 Docstring 就是给大模型看的说明书，写得好不好直接决定大模型会不会调用、参数提取得对不对。
  - **参数类型注解**：必须写 `city: str`，大模型依赖此信息生成 JSON 参数。
  - **必须携带 ID**：构造 `ToolMessage` 时，必须携带 `tool_call_id`，否则大模型会“失忆”。

### 2. Agent 自动执行与流式输出 (Lesson 02 / 03)

- **核心内容**：使用 `create_agent` 构建智能体，`TavilySearch` 联网搜索，`stream_mode="messages"` 实现打字机效果。
- **逻辑流程**：Agent 引擎接管了 Lesson 01 的手动循环，自动完成“思考 -> 调工具 -> 拿结果 -> 继续思考”直到生成最终答案。
- **重点/坑点**：
  - **数据过滤**：流式输出时（`stream_mode="messages"`），底层工具的原始 JSON 和中间状态也会流出来。必须通过 `metadata.get("langgraph_node") == "tools"` 过滤，只保留 AI 生成的文本。
  - **时间幻觉（致命坑）**：大模型默认不知道今天是哪天。必须在 `system_prompt` 中使用 `datetime.now()` 动态注入当前系统时间。否则模型可能去搜索“2024年”的历史天气并给出错误答案。

### 3. MCP 协议接入外部生态 (Lesson 04)

- **核心内容**：使用 `MultiServerMCPClient` 接入 ModelScope 提供的 12306 订票 MCP 服务。
- **逻辑流程**：客户端拉取服务端暴露的 Tools -> 统一注入到 `create_agent` 中 -> 用户提问后，大模型直接生成符合 MCP 协议参数的调用请求。
- **重点/坑点**：
  - **协议转换**：视服务端实现而定，`transport` 字段常常需要配置为 `"sse"` 或 `"http"` 才能连通。
  - **错误兜底**：必须为拉取到的工具配置 `handle_tool_error`，防止第三方接口网络超时导致整个 Python 进程崩溃。

### 4. 会话记忆与上下文保持 (Lesson 05)

- **核心内容**：基于 `InMemorySaver` 和 `thread_id` 实现多轮对话。
- **逻辑流程**：首次对话将数据存入 Saver 并与 `thread_id` 绑定 -> 二次对话携带相同的 `thread_id` -> 引擎自动拼接历史记录发给大模型。
- **重点/坑点**：
  - **必须传入 checkpointer**：在 `create_agent` 时若不加 `checkpointer=memory`，即使传了 `thread_id` 也不会生效。
  - **Token 爆炸**：Agent 如果返回了超长结果（如 55 趟高铁车次），会全部存入内存。多轮对话后上下文会迅速膨胀，耗费大量 Token。

### 5. 中间件与人工审核 (Lesson 06)

- **核心内容**：使用 `HumanInTheLoopMiddleware` 拦截敏感操作（如大额转账）。
- **逻辑流程**：大模型决定调用敏感工具 -> 中间件拦截并抛出 `__interrupt__` -> 程序暂停，等待人工输入指令 -> 用户同意（`approve`）或拒绝（`reject`） -> 通过 `Command(resume=...)` 恢复执行。
- **重点/坑点**：
  - **异步上下文问题**：在 Python 3.10 下用异步方式运行 HITL 中间件时，极易报 `Called get_config outside of a runnable context`。需要使用子类包装 `copy_context()` 进行修复（或降级为同步的 `invoke`）。

## 二、 完整 Agent 工作流程与核心注意点

开发一个企业级的 Agent 应用，通常分为**环境构建阶段**与**交互执行阶段**。

### 🔄 阶段一：环境构建与初始化（前期准备）

1. **定义工具集**：使用 `@tool` 封装本地函数，或通过 `MCP Client` 拉取远程工具。
2. **配置大模型**：初始化 LLM，建议 `temperature=0` 以保证工具参数提取的准确性。
3. **注入环境信息**：在 `system_prompt` 中注入当前时间、用户角色等背景信息。
4. **配置记忆引擎**：实例化 `InMemorySaver`（或持久化的 SqliteSaver）并传给 Agent。
5. **配置安全拦截（可选）**：定义 `HumanInTheLoopMiddleware` 并声明哪些工具需要人工审批。

### 🔄 阶段二：运行与交互过程（在线使用）

1. **用户输入**：接收用户 Query。
2. **大模型思考**：判断是否需要调用工具，提取参数。
3. **工具拦截**：如果是敏感工具，抛出中断，暂停并等待人工决策（通过 `Command` 恢复）。
4. **工具执行**：调用本地函数或远程 API 获取数据。
5. **结果回传**：将 `ToolMessage` 交还给大模型。
6. **循环往复**：直到大模型认为信息足够，输出最终自然语言回复。

### ⚠️ 核心避坑指南（对比 RAG 的差异）

- **模型能力差异极大**：RAG 中任何模型都能做向量检索，但在 Agent 中，强模型（GPT-4o）调用工具一次命中，弱模型（glm-air）会反复调用、自我纠错甚至陷入死循环。**Agent 的成功率高度依赖底层模型的智商**。
- **安全红线**：绝不能让大模型直接执行删除数据库、转账等操作。`HITL` 中间件是 Agent 上线的必须品。
- **异步陷阱**：LangGraph 及底层 MCP 大量采用异步实现（`asyncio`），在 `async def` 函数中，必须坚持使用 `await agent.ainvoke()` 或 `astream()`，一旦混用同步方法，极易导致上下文丢失或事件循环阻塞。
