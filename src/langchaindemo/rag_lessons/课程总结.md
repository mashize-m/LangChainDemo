# 课程重点

### 1. 基础模型调用 (Lesson 01)

- **重点技术点**：
  - **模型初始化**：使用 `init_chat_model` 统一封装，兼容 OpenAI、DeepSeek 等不同厂商模型。
  - **四种核心调用方式**：同步 `invoke`、异步 `ainvoke`、流式 `stream`（打字机效果）、批次 `batch`（并发处理）。
  - **结构化输出**：结合 `Pydantic` 和 `JsonOutputParser` 强制大模型返回 JSON 格式数据。
  - **提示词模板**：使用 `ChatPromptTemplate` 动态注入变量。

### 2. Markdown 文档加载与切分 (Lesson 02 / 03)

- **当前主流方案**：对于 Markdown，主流做法是使用原生语法解析（轻量级）或借助 NLP 语义拆分库（重量级）。目前 RAG 业界极度推荐轻量级方案。
- **两种方案对比**：
  - **02 轻量级（推荐）**：依赖极轻、速度极快、元数据干净，但在非标准 Markdown 语法前失效。
  - **03 重量级**：深度语义拆分（区分标题、列表、正文），但依赖极重（NLTK/magic），Windows 下极易卡死，且拆得过于细碎（丢失宏观上下文）。
- **逻辑处理流程**：
  - **02 轻量流程**：一级切分（按 `#` 标题） -> 二级切分（按 500 字符） -> 栈逻辑重构上下文（拼接所属章节）。
  - **03 重量流程**：`Unstructured` 深度拆解 -> 遍历所有元素 -> 利用**栈算法**（遇到 Title 入栈，遇到正文出栈拼接）重组上下文。
- **使用、限制与注意事项**：
  - `MarkdownHeaderTextSplitter`：**限制**是只能识别规范的 `#` 标题，对正文内的 HTML、复杂表格无法特殊处理。**注意**一级切分后必须用 `RecursiveCharacterTextSplitter` 做二级兜底，防止单块过长。
  - `UnstructuredMarkdownLoader`：**限制**是极度吃性能和网络环境。**注意**传入 `mode="elements"` 才会拆分成细粒度元素，且必须手写栈算法把标题拼回去。

### 3. Word 文档加载与切分 (Lesson 04 / 05)

- **当前主流方案**：轻量级提取文本 + 正则清洗；或使用重量级库直接做结构化解析。
- **两种方案对比**：
  - **04 轻量级（推荐）**：提取纯文本极快，无环境依赖。缺点是完全丢失标题层级，需要自己写正则修排版。
  - **05 重量级**：理论上能识别结构，但面对国内排版不规范的 Word（不使用样式），会完全失效（全部识别为未分类文本），且元数据极度臃肿。
- **逻辑处理流程**：
  - **04 轻量流程**：`Docx2txt` 提取文本 -> 正则清洗（修复单字换行、去页码） -> 正则匹配“第X章” + 栈逻辑一级切分 -> 二级长度切分 -> 路径拼接。
  - **05 重量流程**：`Unstructured` 加载 -> 用正则匹配内容强制重建栈 -> 替换原有错误的元数据。
- **使用、限制与注意事项**：
  - `Docx2txtLoader`：**限制**是纯文本提取，完全丢失图片、表格格式。**注意**必须编写强力的正则表达式（如 `(?<=\n)(\S)\n(?=\S)`）来清理 Word 转换带来的单字换行噪音。
  - `UnstructuredWordDocumentLoader`：**限制**是如果在 Word 中没有使用“标题1/标题2”样式，它的结构识别会完全崩溃。**注意**不能依赖它的 `category` 字段，要用正则强判断。

### 4. PDF 文档解析与清洗 (Lesson 06 / 07)

- **当前主流方案**：针对复杂版式 PDF，目前主流是使用基于视觉的解析模型（如 MinerU、Docling）。课程使用的是 **MinerU API**。
- **逻辑处理流程**：
  - **06 API 调用**：申请上传链接 -> PUT 上传 -> 轮询获取解析状态 -> 返回 ZIP 结果包。
  - **07 解析清洗**：下载解压 -> 提取 Markdown -> **表格保护** -> 两级切分 -> **大表拆分** -> 严格清洗（去封面、图注）。
- **通用重点（三大法则）**：
  1. **表格保护**：通过正则抽离 `<table>` 并替换为占位符，防止被长度切分器拦腰砍断。
  2. **大表拆分**：表格还原时若超长（>1500字符），按 `<tr>` 行截断，并将表头复制到每个子表，保证大模型能看懂列名。
  3. **数据清洗**：过滤纯图片块、封面块（无标题且字数极少），规范图片语法。
- **当前代码特定重点**：MinerU 的输出质量极高，已自动将公式转为 LaTeX，表格转为 HTML。因此在清洗时，重点在于保留 HTML 标签，不要被正则误删。

### 5. 向量化 (Lesson 08 / 09)

- **向量化常用模型与主流方案**：
  - **常用模型**：OpenAI 的 `text-embedding-ada-002/3`、智源的 `BGE` 系列、MokaAI 的 `M3E` 系列等。
  - **当前主流**：对于中文 RAG，**BGE 系列**（如 `bge-base-zh-v1.5`、`bge-m3`）是绝对的主流。它们在中文语义匹配上表现极佳，且维度适中（768/1024），支持长文本。
  - **调用方式（不只能本地调用）**：
    - **本地部署调用（本项目采用）**：使用 `HuggingFaceEmbeddings` 或 `FlagEmbedding` 加载本地的模型文件，利用本地 CPU/GPU 推理。**优点**：完全免费、断网可用、数据安全；**缺点**：吃本地算力。
    - **云端 API 调用**：通过 `OpenAIEmbeddings` 或各大云厂商（如阿里、智谱）的 API 接口调用。**优点**：无需本地算力；**缺点**：按量收费、需联网、数据出网。
    - **Ollama 本地服务化**：在本地用 Ollama 跑起向量模型，然后通过 HTTP 接口（像调用 API 一样）调用。
- **什么是向量化？**
  - 向量化（Embedding）是将文本、图片等非结构化数据，通过深度学习模型映射到一个高维数学空间，变成一组数字（如 768 维或 1024 维的浮点数数组）的过程。在这个高维空间里，**语义相近的文本，其向量在空间中的距离（或夹角）就越近**。
- **为什么需要索引类型和度量方式？**
  - 当向量库里有百万、千万条数据时，如果新来一个问题向量，我们要找它跟库里哪个向量最相似。**索引类型**决定了如何以极快的速度在浩瀚的数据中筛选出候选集（避免逐一比对）；**度量方式**决定了用什么数学公式来精确计算这两个向量到底有多相似（算距离还是算夹角）。
- **索引类型（Index Type）全景图**：

| 索引类型                  | 适用对象     | 核心原理                 | 适用场景                                           | 优缺点                                            |
| :------------------------ | :----------- | :----------------------- | :------------------------------------------------- | :------------------------------------------------ |
| **HNSW**                  | **稠密向量** | 分层图导航               | **主流推荐**。千万级数据，要求极高召回率和极快响应 | **优**：检索极快，召回率高。 **缺**：内存占用大。 |
| **FLAT**                  | **稠密向量** | 暴力穷举比对             | 十万条以下小数据，或作测试基准                     | **优**：100% 精确。 **缺**：数据量大时极慢。      |
| **IVF_FLAT**              | **稠密向量** | 聚类倒排                 | 百万级数据，内存有限                               | **优**：比 FLAT 快，省内存。 **缺**：需调参。     |
| **SPARSE_INVERTED_INDEX** | **稀疏向量** | 倒排索引（类似搜索引擎） | **稀疏向量唯一选项**。关键词精确匹配               | **优**：极快。**缺**：仅适用稀疏字典。            |

- **度量方式（Metric Type）与归一化**：
  - **什么是归一化？** 将向量的长度（L2范数）缩放为 1。在初始化 BGE 模型时设置 `encode_kwargs={"normalize_embeddings": True}` 即可。归一化后，**内积（IP）等价于余弦相似度（COSINE）**。

python

```
// src/langchaindemo/lessons/lesson08_embedding.py 文件的 embedding_demo()函数，初始化 `HuggingFaceEmbeddings` 时传入的参数

embed_model = HuggingFaceEmbeddings(
    model_name=str(BGE_MODEL_PATH),
    model_kwargs={"device": "cpu"},
    encode_kwargs={"normalize_embeddings": True} # <--- 这里就是归一化
)
```



| 度量方式          | 计算逻辑         | 分数倾向   | 适用情况                                     |
| :---------------- | :--------------- | :--------- | :------------------------------------------- |
| **IP (内积)**     | 向量点乘 (A·B)   | 越大越相似 | **稀疏向量（固定）**；稠密向量（未归一化）。 |
| **L2 (欧式)**     | 两点间直线距离   | 越小越相似 | 稠密向量（未归一化）。                       |
| **COSINE (余弦)** | 两向量夹角余弦值 | 越大越相似 | **稠密向量（已归一化，主流推荐）**。         |

- **选型指南（谁该搭配谁？）**：
  - **针对稠密向量（主流做法）**：模型已归一化。索引选 `HNSW`，度量选 `COSINE`（或 `IP`、`L2`，排序结果等价，但 COSINE 分数最直观）。
  - **针对稀疏向量（唯一做法）**：无须归一化。索引必须选 `SPARSE_INVERTED_INDEX`，度量必须选 `IP`。

### 6. 向量存储和检索 (Lesson 10 - 14)

- **重要步骤（Milvus 核心操作流）**：
  1. **建表与索引（10）**：定义 Schema（主键、Dense、Sparse、标量字段），创建 HNSW 和倒排索引，并 `load` 到内存。
  2. **数据插入（11）**：将向量化后的实体（包含向量、原文、元数据）批量插入。
  3. **数据删除（12）**：通过主键 ID 或条件表达式（如 JSON 属性过滤）删除数据。
  4. **向量检索（13）**：通过 Dense、Sparse 或混合检索召回 Top-K 数据。
  5. **标量过滤（14）**：通过 `text like` 或 `metadata` 表达式进行条件检索或元数据过滤。
- **索引创建的注意事项**：
  - **维度必须一致**：建表时的向量维度（如 1024），必须与 Embedding 模型输出的维度严格一致。
  - **Metric 必须匹配**：建表时用的度量方式（如 COSINE），在后续检索时传入的 `search_params` 也必须一模一样，否则 Milvus 会直接报错。
  - **数据类型转换**：向 Milvus 插入时，必须将 Numpy 类型的向量转为 Python 原生 `list`（`dense_vec.tolist()`）和 `dict`（`float(v)`）。
- **检索的注意事项**：
  - **RRF 融合重排**：混合检索时，稠密分数和稀疏分数不在一个量级。必须使用 `RRFRanker`，它只看排名不看绝对分数，完美融合两路结果。
  - **软删除机制**：`client.delete()` 后，数据立刻无法被 `search` 或 `query` 查到，但底层的物理空间释放需要等后台 Compaction 调度。
  - **元数据穿透查询**：在过滤器中，可以通过 `metadata["title_path"] like "%xxx%"` 直接穿透 JSON 字段查询，极大提升 RAG 精准度。
  - **重排序（Reranker）与 RRF 的区别及顺序**：
    - **什么是 Reranker？** 它是一种**精排模型**（通常是 Cross-Encoder 架构）。向量检索（双塔模型）为了速度，往往召回“大概相关”的 Top-20。Reranker 会把这 20 个问题和文档逐一拼接，进行深度交叉计算，得出极度精确的分数，截取最相关的前 3 个给大模型。
    - **执行顺序（完整链路）**：
      1. **多路召回**：Dense 检索得出 Top-20，Sparse 检索得出 Top-20。
      2. **RRF 融合（多路合并）**：使用 RRF 算法将两路结果合并成一个去重后的 Top-20 列表。*（我们的 Lesson 15 代码停在了这一步，直接交给了大模型）*
      3. **Reranker 重排序（精准打分）**：将合并后的 Top-20 列表，喂给 Reranker 模型进行二次打分，选出得分最高的 Top-3。*（这是进阶优化步骤，用于应对极高准确性要求的场景）*。

### 7. RAG 问答闭环 (Lesson 15)

- **逻辑处理流程**：用户输入 Query -> BGE-M3 生成混合向量 -> Milvus 混合检索（Top-3） -> 提取文本和 `title_path` 拼接为 Context -> 组装强约束 Prompt -> 大模型生成答案。
- **重点内容**：
  - **降维打击**：Prompt 中必须强约束“如无法从资料中获取答案，请直接回答无法回答”，极大降低幻觉。
  - **温度调节**：RAG 场景必须调低 `temperature`（如 0.1），让模型输出收敛，忠于原文。
  - **元数据赋能**：将 `title_path` 拼接到正文中给大模型看，大模型在解读表格数据时能明确知道“这是哪张表格的哪一列数据”，大幅提升准确率。
