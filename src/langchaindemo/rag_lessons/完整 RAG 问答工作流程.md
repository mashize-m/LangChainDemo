# 完整 RAG 问答工作流程与核心注意点

一个工业级的 RAG（检索增强生成）系统，其运转逻辑可以严格划分为两个阶段：**前期准备（离线索引）**与**使用过程（在线推理）**。

------

## 一、 前期准备工作流程（离线索引阶段）

**目标**：将多源异构的原始文档，经过解析、清洗、切分、向量化后，转化为 Milvus 数据库中可被高效检索的“向量+元数据”。

### 🔄 核心工作流程

1. **文档解析（Parsing）**：读取本地文件（MD、Word、PDF），将其转化为纯文本或带有结构的 Markdown。
2. **文本切分（Chunking）**：采用“一级结构 + 二级长度”双重切分，将长文档切为 500 字符左右的片段。
3. **数据清洗与增强（Cleaning & Enrichment）**：过滤无效块，并将章节标题（如 `【所属章节】: 第一编 > 第一章`）强制拼接进正文开头。
4. **向量化（Embedding）**：调用 BGE 模型，将每个文本块同时转化为稠密（Dense）和稀疏（Sparse）向量。
5. **入库与索引（Indexing）**：在 Milvus 中建立集合，构建向量索引，将数据批量写入。

### ⚠️ 重点注意事项

- **文档解析的降维打击**：面对复杂 PDF，坚决使用 MinerU 等视觉模型，直接将表格转为 HTML，公式转为 LaTeX，避免传统提取导致的格式错乱。
- **切分中的“表格保护”**：绝不能直接对包含 `<table>` 的文本按长度硬切。必须先用正则抽离表格，如果表格超长，需按行（`<tr>`）拆分，并将**表头复制到每个子表**中，否则大模型看不懂列名。
- **清洗必须彻底**：必须剔除目录块、纯图片块（如果业务不需要图）、封面块（无标题且字数极少），防止这些“垃圾数据”被检索出来污染大模型的判断。
- **模型维度的对齐**：此处生成的向量维度（如 BGE-base 的 768 维，BGE-M3 的 1024 维），必须与下一步建表时的字段维度完全一致。
- **数据类型转换**：BGE 模型输出的向量是 Numpy 格式，在 `insert` 进 Milvus 前，必须转换为原生的 Python `list`（Dense）和 `dict`（Sparse），否则底层会报错。

------

## 二、 使用过程工作流程（在线推理阶段）

**目标**：接收用户提问，快速从海量数据中精准召回相关知识，并由大模型生成可靠回答。

### 🔄 核心工作流程

1. **用户提问（Query）**：接收用户输入的自然语言问题。
2. **问题向量化（Query Embedding）**：使用与前期准备**完全相同**的 BGE 模型，将问题转化为稠密和稀疏向量。
3. **混合检索（Hybrid Search）**：在 Milvus 中同时发起 Dense（语义）和 Sparse（关键词）检索，并使用 `RRFRanker` 算法合并两路召回结果。
4. **上下文组装（Context Assembly）**：提取检索结果中的正文和 `metadata`，拼装成结构化的参考资料。
5. **Prompt 生成（Generation）**：将参考资料与用户问题注入预设的提示词模板，调用大模型生成最终答案。

### ⚠️ 重点注意事项

- **检索参数严格匹配**：查询时的 `metric_type`（如 COSINE、IP、L2）必须与前期建索引时一模一样，否则 Milvus 直接报错。
- **RRF 融合重排的作用**：稠密检索分数（如 0.8）和稀疏检索分数（如 15.2）不在一个量级，无法直接相加。RRF 算法**不看绝对分数，只看排名**，将两路 Top-K 结果公平融合。
- **防止幻觉的强约束**：System Prompt 中必须强硬性规定：“请严格根据参考资料回答；如果资料中找不到，请直接回答‘根据提供的资料无法回答’”。
- **温度参数（Temperature）**：RAG 场景不是写小说，`temperature` 建议设为 `0.0` ~ `0.1`，让大模型输出收敛、严谨、忠于原文。
- **进阶优化 - Reranker 精排**：如果业务对精度要求极高，可以引入 Reranker（如 BGE-Reranker）对 RRF 融合后的 Top-20 结果进行深度交叉计算打分，截取最精准的 Top-3 给大模型。
